PROJECT: RANDOMISER
MVP STRUCTURE WITH WEB MODE AND BATCH MODE

Purpose:
This structure keeps the project MVP-first while adding a lightweight web app
integration. The project now has two supported run modes:

1. Web mode:
   A web page that shows the intuitive working process:
   source collection -> source transformation -> health gate -> fusion ->
   conditioning -> OTP output.

2. Batch mode:
   A long-running VS Code / terminal workflow that generates many OTP runs
   continuously and saves every run in a structured experiment folder.

Both modes use the same source modules, pipeline modules, and experiment
storage layout.

========================================================================
2. EXPERIMENT STORAGE CONTRACT
========================================================================

Every experiment gets its own folder:

data/experiments/<experiment_id>/

Inside each experiment:

input/
  camera/
  microphone/
  cpu_jitter/
  scheduler_jitter/

output/
  run_index.csv

logs/

All source files from one OTP run share the same filename stem.

Example run id:
run_000001

Matching input files:
input/camera/run_000001.bin
input/microphone/run_000001.bin
input/cpu_jitter/run_000001.bin
input/scheduler_jitter/run_000001.bin

Output CSV row:
run_id,mode,camera_input_file,microphone_input_file,cpu_jitter_input_file,scheduler_jitter_input_file,otp,status,created_at


========================================================================
3. WHY THIS SHAPE FITS THE PROJECT NOW
========================================================================

1. The web app is added without turning the repo into a heavy research app.
2. Web mode and batch mode share the same pipeline and storage code.
3. The web page can show each transformation step using trace/ modules.
4. Batch mode can run continuously and write stable experiment records.
5. The data folder now has a clear source-input to OTP-output mapping.
