PROJECT: RANDOMISER
MVP-FIRST PROPOSED FILE STRUCTURE

Purpose:
This structure replaces the earlier research-heavy scaffold with a smaller
implementation-first layout. It keeps only what is needed to build the
generator MVP cleanly, while leaving room to add analysis, apps, and research
artifacts later.

Main design goals:
1. Keep the entropy generator pipeline small and understandable.
2. Separate source collection, pipeline logic, logging, and CLI.
3. Keep only the configs, docs, scripts, and tests needed for the MVP.
4. Remove dashboard, ML, reporting, notebook, and infrastructure clutter for now.

Removed from the current scaffold:

- notebooks/
- reports/
- infra/
- .github/
- src/randomiser/analysis/
- src/randomiser/ml/

These can be added back later after the generator MVP is working end to end.


========================================================================
3. WHY THIS MVP STRUCTURE IS BETTER RIGHT NOW
========================================================================

1. It reduces noise.
The repo focuses on building the generator instead of pretending the whole
research platform already exists.

2. It keeps the main implementation path obvious.
The important code is now under:
- sources/
- pipeline/
- io/
- cli/

3. It avoids premature surface area.
No dashboard, API, notebooks, or ML attack layer until the entropy pipeline
itself is real and tested.

4. It still leaves a clean upgrade path.
Later additions can be reintroduced without restructuring the core package.
